# 재고관리 앱 — 7단계 스펙: 반응형 레이아웃 분기

## 배경

로드맵 7단계(반응형 레이아웃 분기, 여기서 윈도우 대응 붙임)에 대한 스펙이다. 1~6단계(도메인 모델, 로컬 DB, 입고 등록, 재고 조회, 폐기/조정, 마감 실사)는 이미 구현/테스트/커밋 완료된 상태이며, 지금까지는 화면마다 `Navigator.push`로 이동하는 홈 화면(버튼 6개) 구조였다. 이번 스펙은 그 자리에 데스크톱/모바일에 맞는 반응형 네비게이션 셸을 넣는다.

## 이번 스펙의 범위

- 화면 너비 600px을 기준으로 데스크톱(사이드바)/모바일(하단 탭) 레이아웃을 자동으로 전환하는 `AppShell`
- 모바일의 "더보기" 진입점(거래처 관리/품목 관리로 가는 목록 화면)
- `HomeScreen`(버튼 6개짜리 임시 홈 화면) 제거

**범위 밖** (다음 단계에서 다룸): 마지막으로 보던 탭을 기억해뒀다가 재실행 시 복원하는 기능(사용자가 이번 단계에서 명시적으로 다음으로 미룸), 서버 동기화(8단계), 안전재고 알림(9단계).

## 전제/결정 사항

- **네비게이션 구조**: 시각 동반자로 두 가지 안(A: 사이드바+하단탭 4개, B: 사이드바+햄버거 드로어)을 비교한 뒤 **A**로 결정했다. 이유: 모바일에서 자주 쓰는 작업(재고조회/입고등록/마감실사)은 엄지가 바로 닿는 하단 탭에 두고, 가끔 쓰는 관리 작업(거래처/품목 관리)은 "더보기" 뒤로 미뤄서 사용 빈도에 맞게 접근성을 차등화한다.
- **기준선(breakpoint)**: 화면 너비 **600px** (Flutter/Material이 관례적으로 쓰는 기본값). 600px 미만은 모바일 레이아웃, 이상은 데스크톱 레이아웃.
- **홈 화면 처리**: 사이드바/하단탭 자체가 이미 메뉴 역할을 하므로, 버튼만 있는 기존 홈 화면은 없앤다. 앱을 실행하면 바로 **재고 조회 화면**이 기본으로 뜬다.
- **탭 상태 유지 여부**: 이번 단계 범위 밖. 항상 재고 조회로 시작하는 것으로 고정하고, "마지막 탭 기억" 기능은 다음 단계로 미룬다.
- **모바일 "더보기"**: 하단 탭의 4번째 항목이지만, 다른 탭과 달리 상태를 바꾸지 않고 `MoreScreen`(거래처 관리/품목 관리로 가는 목록)을 위로 띄우는 일회성 동작이다.

## 아키텍처

새 위젯 `AppShell`이 `MediaQuery`로 현재 화면 너비를 읽어 두 레이아웃 중 하나를 그린다.

**데스크톱(≥600px)**: `NavigationRail`(왼쪽 고정) + 오른쪽에 선택된 화면. 목적지 5개: 재고조회, 입고등록, 마감실사, 거래처관리, 품목관리 — 전부 평평하게 나열(화면이 넓어서 "더보기"로 묶을 필요가 없음).

**모바일(<600px)**: `BottomNavigationBar`(4개: 재고/입고/실사/더보기) + 선택된 화면. "더보기" 탭 시 `Navigator.push`로 `MoreScreen`을 띄운다.

**핵심 기술 결정 — `IndexedStack`**: 탭 전환은 `Navigator.push`가 아니라 `IndexedStack`으로 처리한다. 탭을 오갈 때 입력하던 폼 값이나 스크롤 위치가 유지된다. 대신 IndexedStack의 모든 자식 위젯이 처음부터 동시에 마운트된 상태로 유지된다는 특성이 있다 — 즉 재고조회·마감실사 화면의 Drift `.watch()` 스트림 구독이 앱 실행 시점부터 항상 활성 상태다. 로컬 SQLite 스트림 몇 개는 이 앱 규모에서 부담이 없는 수준이라 문제 삼지 않는다.

## 파일 구조

```
lib/
  core/
    shell/
      app_shell.dart     # 반응형 레이아웃 분기 + IndexedStack
      more_screen.dart    # 모바일 "더보기" 목록 화면
  main.dart                # HomeScreen 삭제, AppShell로 교체
```

`HomeScreen`은 이번 스펙에서 완전히 제거된다(대체된 죽은 코드를 남기지 않는다).

## 테스트 전략

- 넓은 화면(1000×800)에서 `NavigationRail`과 5개 목적지 라벨이 뜨는지, 목적지를 탭하면 해당 화면(`find.byType`)으로 바뀌는지
- 좁은 화면(360×800)에서 `BottomNavigationBar`(4개)가 뜨고 `NavigationRail`은 없는지, "더보기" 탭 시 `MoreScreen`이 위로 뜨고 그 안의 항목이 거래처/품목 관리로 이동하는지
- 탭을 전환했다가 돌아와도 폼에 입력하던 값이 남아있는지(IndexedStack 상태 유지 검증) — 입고 등록 화면의 수량 필드로 확인
- 화면 크기 제어는 `tester.view.physicalSize`/`devicePixelRatio`로 테스트마다 명시적으로 지정 (기본값에 의존하지 않음) — 구현 중 `tester.binding.setSurfaceSize(...)`가 이 Flutter 버전에서 `MediaQuery`에 반영되지 않는 걸 발견해서 `tester.view` API로 교체했다
