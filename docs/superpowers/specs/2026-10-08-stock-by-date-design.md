# 재고관리 앱 — 날짜별 재고 조회 스펙

## 배경

재고 조회는 "지금" 재고만 보여준다. 어제나 지난주 끝에 얼마가 있었는지, 오늘 어떤 재고가 들어왔는지는 볼 수 없다. 재고는 입출고 기록(`StockMovement`)을 로트별로 더한 값이라 과거 시점의 재고는 기록을 거슬러 합하면 구할 수 있고, 따로 저장할 것이 없다.

이 스펙은 재고 조회 화면에 **날짜 선택**과 **그날 입고 목록**을 더한다.

## 이번 스펙의 범위

- 재고 조회 상단바에 날짜 버튼. 오늘이 기본값이고 미래 날짜는 고를 수 없다.
- 고른 날짜 **끝 기준 재고**를 품목 카드로 보여준다.
- 요약 줄 아래에 **"이 날 입고 N건" 카드**. 그날 들어온 로트를 한 줄씩 보여준다.
- 지난 날짜는 **조회 전용**이다.

**범위 밖**
- 그날의 모든 변동(폐기·조정·실사 보정)을 시간순으로 보는 화면 — 사용자가 고르지 않았다 (처음 질문의 3번).
- 두 날짜 비교, 기간 합계, 엑셀로 내보내기.
- 새 테이블, 동기화 변경, Supabase SQL — 없다.
- 입고일을 직접 고르는 입고 화면 변경 — 지금 입고일은 입력한 순간(`DateTime.now()`)이다.

## 전제/결정 사항

**사용자가 정한 것**
1. 날짜를 고르면 **그날 끝 기준 재고 + 그날 들어온 것**을 둘 다 본다.
2. 입고 목록은 재고 목록 위쪽 카드로 둔다 (탭으로 나누지 않는다).

**제가 정한 기본값 (스펙 검토 때 바꿀 수 있다)**
3. 직원도 날짜를 고를 수 있다. 매장 범위는 지금과 같다 (직원은 자기 매장, 사장은 `activeStoreIdProvider`).
4. 지난 날짜에는 탭 이동(폐기·조정 화면), 화살표, "임박" 표시를 두지 않는다. 기록을 보는 화면이라 지금 시점의 행동 단서가 의미 없다.
5. 오늘은 지금처럼 로트의 `remainingQty`를 쓰고 실시간으로 갱신된다. 지난 날짜만 기록 합계로 계산한다.
6. 하루의 경계는 기기의 **로컬 자정**이다 (한국 매장 기준).

## 계산

날짜 `D`의 끝 = `D+1일 00:00` (로컬). 날짜 선택값은 시각 없는 날짜로 다룬다.

**D 끝 기준 재고** — 로트별로 `occurredAt < D+1일 00:00`인 `StockMovement.quantity`의 합. 합이 0 이하인 로트는 제외한다. 이후 품목별로 묶는 것은 지금과 같은 `groupLotsByIngredient` 계열이다.
- 한 번의 쿼리로 한다: `StockMovements`를 `Lots`·`Ingredients`와 조인하고, 매장 조건과 시각 조건을 걸고, `lotId`로 묶어 합계를 구한다.
- 입고 기록의 `occurredAt`은 입고 시각이고 이후의 변동은 부호가 있는 기록이므로, 합이 그 시점의 수량이다.

**D의 입고 목록** — `type == 'inbound'` 이고 `D 00:00 <= occurredAt < D+1일 00:00`인 기록, 해당 로트·품목·매장·거래처와 조인. 입고일 순으로 정렬한다. 수량은 기록의 `quantity`(입고 시 수량)이고 이후 폐기·조정으로 줄어든 현재 수량이 아니다.

> 입고 목록의 기준은 **입력한 날**이다. 입고일을 따로 고르는 칸이 없기 때문이다.

## 화면

- 상단바: `날짜 버튼`(오늘이면 "오늘", 아니면 "10월 5일")과 기존 `StoreSwitcher`. 버튼을 누르면 `showDatePicker`(`lastDate`=오늘).
- 날짜가 오늘이 아니면 목록 위에 "10월 5일 기준 (조회 전용)" 안내와 "오늘로 돌아가기" 동작을 둔다.
- 요약 줄(재고 품목 N종, 유통기한 임박 N건) 아래에 입고 카드.
  - 한 줄 = 품목명 · 수량(기본단위) · 매장 칩 · 거래처. 입고가 없으면 "이 날 입고된 재고가 없습니다" (오늘 화면에서는 "오늘 입고된 재고가 없습니다").
  - **구현 중 사용자가 정한 변경:** 입고가 4건 이상이면 카드에는 처음 3건만 보이고 "전체 N건 보기"가 그날 입고 전체 화면(`InboundDayScreen`)을 연다. 품목 카드는 로트가 4개 이상이면 처음 3줄만 보이고 "나머지 N개 보기"로 그 자리에서 펼친다 (임박 로트는 접혀도 항상 보인다). 상단바 날짜 버튼은 폭 600 미만에서 아이콘만 남는다 (툴팁 "날짜 선택 (오늘)").
  - 지난 날짜에서는 요약 줄의 "유통기한 임박"을 숨긴다 (지금 기준 값이라 그날 기준으로는 틀리다).
- 품목 카드는 지금 구조를 따른다. 지난 날짜에서는 `_LotRow`가 눌리지 않고 화살표가 없다.
- 재고가 없는 날의 빈 상태 문구는 날짜가 오늘이 아닐 때 "이 날에는 표시할 재고가 없습니다"로 다르게 한다.

## 코드 구조

- `lib/domain/stock_by_date.dart` — 하루 경계 계산(`dayStart`, `dayEnd`)과 결과 모델(`InboundEntry`).
- `LotDao` 또는 `StockMovementDao`에 두 쿼리를 추가한다: `watchStockAsOf(date, storeId)`, `watchInboundOn(date, storeId)`. 둘 다 `Stream`.
- `lib/core/providers/` 에 선택 날짜 `StateProvider<DateTime?>`(`null` = 오늘). 매장이 바뀌어도 날짜는 유지하고, 재고 조회 화면을 벗어나면 오늘로 돌아가지 않아도 된다 (단순함을 택한다).
- `stock_overview_screen.dart`에 날짜 버튼과 입고 카드를 더한다. 파일이 이미 430줄이라 입고 카드는 별도 파일로 뺀다.

## 테스트

- 계산 (DB, 위젯 아님): 지난날 입고 후 오늘 폐기한 로트는 그 날짜에는 폐기 전 수량이 나온다. 합이 0 이하인 로트는 빠진다. 경계: `D 23:59:59`는 D에 포함되고 `D+1 00:00:00`은 제외된다. 매장 범위: 다른 매장 로트는 안 나온다. 전체 합산은 모두 나온다.
- 입고 목록: `inbound`만 들어가고 `usage`·`disposal`·`adjustment`·`countCorrection`은 빠진다. 이후 폐기된 수량이 아니라 입고 시 수량이 보인다.
- 화면: 오늘은 지금 화면과 같다 (기존 재고 조회 테스트 모두 통과). 지난 날짜는 `_LotRow` 탭이 이동하지 않고 화살표가 없다. 입고 카드의 빈 상태. 날짜 버튼에서 날짜를 고르면 화면이 바뀐다.
- 구현 후 변이 확인: 경계를 `<`에서 `<=`로, 입고 필터를 빼기, 매장 조건을 빼기 — 각각 테스트가 실패해야 한다.

## 위험과 한계

- 다른 기기에서 받은 기록이 늦게 도착하면 과거 날짜의 값이 나중에 바뀔 수 있다 (동기화가 늦은 동안만 어긋난다). 서버 쪽 저장 구조는 건드리지 않는다.
- 로컬 DB에 `StockMovement`가 없는 옛 로트(기록 없이 만든 로트)는 지난 날짜 계산에서 빠진다. `receiveLot`은 항상 입고 기록을 함께 쓰므로 현재 앱으로 만든 데이터에는 해당하지 않는다.
- **자정을 넘겨 켜 둔 화면 (알려진 한계, 4단계 검토에서 발견):** "오늘" 화면의 입고 카드는 화면을 그린 시점의 날짜로 쿼리 범위를 고정한다. 화면을 다시 그리는 일(매장·날짜 전환, 창 크기 변경, 앱 재시작)이 없으면 다음 날 아침에도 어제 입고가 "오늘 입고"로 보이고 새 입고는 빠진다. 재고 목록(실시간 스트림)과 날짜 선택기는 영향이 없다. 제대로 고치려면 하루에 한 번 갱신되는 "오늘" provider(Timer + 주입 가능한 시계)가 필요하고, 그러면 화면을 띄우는 다른 테스트의 대기 타이머 검사와 임박 판정의 `now`도 같이 손봐야 해서 이번 범위에서 뺐다. 매장 PC를 밤새 켜 두는 운영이 확인되면 별도 작업으로 한다.
- 기록이 매우 많아지면 지난 날짜 쿼리가 느려질 수 있다. 11개 매장 규모에서는 문제가 아니고, 느려지면 그때 인덱스를 추가한다 (스키마 변경이므로 마이그레이션이 필요하다는 점을 계획에 적는다).
