# 재고관리 앱 — 엑셀 업로드 스펙

## 배경

기존 프로그램(거래처별 거래 내역)과 엑셀에 흩어져 있는 거래처·품목·입고 데이터를 앱으로 옮겨야 한다. 지금은 화면에서 하나씩 입력하는 방법뿐이라 품목 수십 개, 입고 수백 건을 옮기기 어렵다. 이 스펙은 **앱이 내려주는 양식에 채워서 올리면 거래처·품목·입고가 한 번에 등록되는** 기능을 더한다.

## 사용자가 정한 것

1. 파일 양식은 **앱이 내려받게 하는 빈 양식 하나**다. 모든 매장이 같은 양식을 쓴다 (기존 엑셀을 그대로 받지 않는다).
2. 매장은 **업로드할 때 앱에서 고른다.** 파일 하나가 매장 하나다. 양식에 매장 열은 없다.
3. 파일에 오류가 하나라도 있으면 **아무것도 저장하지 않는다** (전부 아니면 전무).
4. 같은 입고가 이미 있으면 **미리보기에서 경고하고, 확인해야 올라간다.** 업로드 이력 테이블은 만들지 않는다.
5. 입고의 **단가 칸이 비면 0으로 저장**하고 미리보기에 건수를 알려 준다.
6. **사장만** 쓴다. 직원 화면에는 메뉴가 없다.

## 이번 스펙의 범위

- 사장 전용 메뉴 "엑셀 업로드": 양식 받기, 매장 고르기, 파일 선택, 미리보기, 올리기, 결과.
- 거래처·품목·입고 세 가지를 한 파일에서 올린다. "초기 재고"는 입고의 한 형태로 올린다 (날짜를 옛날로 적는다).

**범위 밖**
- `.xls`, CSV, 한 파일로 여러 매장, 업로드 이력, 올린 것을 한 번에 되돌리기, 기존 거래처·품목의 수정, 큰 파일 진행률 표시.
- 새 테이블, DB 구조 변경(`schemaVersion` 그대로), 서버(Supabase) 변경 — 없다.
- 기존 프로그램에서 엑셀로 뽑는 방법 (사용자가 양식에 맞게 채운다).

잘못 올린 입고는 지금처럼 재고 조회에서 폐기·조정으로 바로잡는다 (한 번에 되돌리는 기능은 없다 — 위험 절 참조).

## 양식 (앱이 만들어 주는 `.xlsx`)

시트 네 개. 머리글은 1행이고, 데이터는 2행부터다. 읽을 때 **시트 이름과 머리글 이름이 정확히 같아야** 한다 (열 순서는 상관없고 모르는 열은 무시한다).

| 시트 | 열 |
|---|---|
| 안내 | 사용 방법, 열 설명, 예시 (읽지 않는다) |
| 거래처 | 이름, 연락처 |
| 품목 | 품목명, 기본 단위, 구매 단위, 환산계수, 안전재고, 유통기한 관리 |
| 입고 | 날짜, 거래처, 품목명, 수량, 단가, 유통기한 |

- **예시 줄은 데이터 시트에 넣지 않는다.** 읽을 때 데이터로 오해하지 않도록 예시는 "안내" 시트에만 둔다.
- 거래처·품목·입고 시트는 **반드시 있어야** 한다. 줄이 하나도 없어도 된다 (이미 등록된 거래처·품목만 쓰는 경우).
- **환산계수** = 구매단위 1개가 기본 단위로 몇 개인지 (품목 등록 창의 "구매단위 1개 = base unit 몇 개"와 같다). 예: 쌀 20kg 1포 → 기본 단위 `g`, 구매 단위 `포`, 환산계수 `20000`.
- **유통기한 관리**는 `예`/`아니오`. 빈칸은 `아니오`다 (품목 등록 창의 기본값 "켜짐"과 다르게, 빈 줄이 조용히 기한 품목이 되지 않게 한다).

## 읽기·검증 규칙

줄 단위로 검증하고, **모든 오류를 한 번에 모아서** 보여 준다 (첫 오류에서 멈추지 않는다). 오류 메시지는 `<시트> 시트 <줄 번호>번째 줄: <이유>` 형식이고, 줄 번호는 엑셀에서 보이는 번호(머리글이 1)다. 한 번에 보여 주는 오류는 최대 50개이고 넘으면 "외 N개"로 줄인다.

**공통**
- 앞뒤 공백을 지운다. 완전히 빈 줄은 건너뛴다.
- 입고 줄은 최대 3,000개다 (넘으면 오류).
- 셀 값은 문자, 정수, 소수, 날짜 어느 것이든 읽는다 (`excel` 패키지의 `TextCellValue.value`는 `.text`로 읽는다).
- 숫자 칸은 숫자 셀 또는 천 단위 쉼표가 올바르게 들어간 문자(`1,000`)를 받는다. 읽을 수 없는 글자는 오류다 (조용히 0이나 빈칸이 되지 않는다).

**거래처 시트**
- 이름이 비면 오류. 같은 이름(공백 무시)이 시트 안에 두 번 있으면 오류.
- 이미 있는 거래처(이름이 같음)는 새로 만들지 않고, 연락처가 달라도 기존 값을 그대로 둔다.

**품목 시트**
- 품목명이 비면 오류. 같은 이름이 시트 안에 두 번 있으면 오류.
- 기본 단위는 `g`, `ml`, `ea` 중 하나. 구매 단위는 비면 오류.
- 환산계수는 0보다 큰 숫자.
- 안전재고는 빈칸(추적 안 함) 또는 숫자 (품목 화면의 안전재고 입력과 같은 규칙, 읽을 수 없는 글자는 오류).
- 유통기한 관리는 `예`/`아니오`/빈칸.
- **이미 있는 품목**(이름이 같음)인데 파일의 **기본 단위나 환산계수가 다르면 오류**다 (수량 해석이 틀어지는 가장 위험한 경우). 안전재고와 유통기한 관리는 기존 값을 그대로 둔다.

**입고 시트**
- 날짜: 엑셀 날짜 셀, 또는 문자 `2026-09-29`, `2026/09/29`, `26/09/29` (두 자리 연도는 20xx). 읽을 수 없으면 오류, **오늘 이후 날짜는 오류**. 날짜만 있으므로 그날 **09:00(기기 로컬 시간)** 에 입고된 것으로 기록한다.
- 거래처: 비면 오류. 파일의 거래처 시트 또는 이미 등록된 거래처에 있어야 한다 (없으면 오류, 이름이 달라서 새 거래처가 조용히 생기는 일이 없도록).
- 품목명: 비면 오류. 파일의 품목 시트 또는 이미 등록된 품목에 있어야 한다 (없으면 오류).
- 수량: 0보다 큰 숫자 (구매 단위 기준). 저장은 `수량 × 환산계수`(기본 단위)로 한다 (입고 등록 화면과 같은 방식).
- 단가: 빈칸은 0, 아니면 0 이상의 숫자.
- 유통기한: 선택. 날짜 규칙은 입고 날짜와 같고, 입고 날짜보다 이를 수는 없다. 품목이 유통기한 관리가 아니면 값이 있어도 **무시하고 경고**로 센다 (오류가 아니다).

## 중복 의심

저장하기 전에 기존 데이터와 비교한다. 아래가 **모두 같은** 입고가 이미 있으면 "중복 의심"이다.
- 선택한 매장, 거래처, 품목, 입고 날짜(로컬 하루 단위), 저장될 기본 단위 수량, 단가.

미리보기에 중복 의심 건수와 줄 목록을 보여 주고, **"알고 있습니다. 그래도 올리기"를 체크해야 올리기 단추가 켜진다.** 새 거래처·새 품목이 걸린 줄은 기존 입고가 있을 수 없으므로 비교하지 않는다. 파일 안의 줄끼리 같은 경우는 중복으로 보지 않는다 (같은 날 같은 품목을 같은 수량으로 두 번 받는 일은 진짜로 있다).

## 화면

- **엑셀 업로드 화면**: "양식 받기" 단추 (저장 대화상자 → `.xlsx`). 매장 고르기 (사장은 목록에서 고른다, "전체 합산"은 선택으로 치지 않는다 — 입고 등록과 같은 규칙, 고르지 않으면 "매장을 선택해주세요"). "파일 선택" 단추 (`.xlsx`만).
- **미리보기**:
  - 요약: 새 거래처 N, 새 품목 N, 입고 N건, 단가 없음 N건, 경고(유통기한 무시) N건, 중복 의심 N건, 오류 N줄. 입고 날짜 범위.
  - 입고 줄 앞쪽 10줄을 `품목명 · 2포 × 20,000 = 40,000g` 형태로 보여 준다 (환산계수를 잘못 적은 것을 올리기 전에 눈으로 잡도록). 더 있으면 "외 N건".
  - 오류가 있으면 오류 목록만 보이고 "올리기"는 없다. "다른 파일 선택"으로 돌아간다.
  - 오류가 없으면 "올리기" 단추. 중복 의심이 있으면 위의 체크가 필요하다.
- **결과**: "거래처 N, 품목 N, 입고 N건을 등록했습니다" 안내와 화면 비우기 (탭 화면이므로 `Navigator.pop()` 하지 않는다 — CLAUDE.md의 탭 화면 규칙).
- **메뉴**: 사장에게만 보인다. 데스크톱은 내비게이션 레일, 폰은 더보기 안에 둔다. 인덱스 처리는 계획에서 `app_shell.dart`를 읽고 정한다 (지금 사장 전용 항목이 인덱스 6, 7에 있다).

## 저장

- 한 트랜잭션 안에서 새 거래처 → 새 품목 → 입고 순으로 만든다. 입고는 `LotRepository.receiveLot`을 쓴다 (날짜를 옛날로 줄 수 있고, 로트와 입고 기록이 함께 써지며, 각 삽입이 동기화 큐에 같은 트랜잭션으로 쌓인다).
- 어느 단계든 예외가 나면 트랜잭션이 전부 되돌려져 아무것도 남지 않는다.
- 저장 후 다른 기기로는 기존 입고와 같은 경로(동기화 큐)로 간다.

## 코드 구조

- `lib/domain/excel_import/` — 시트 셀 값 → 줄 모델, 검증 규칙, 오류 모델 (DB·파일 없음, 순수 함수).
- `lib/data/import/` — 양식 만들기, `.xlsx` 읽기(바이트 → 셀 값), 중복 조회, 한 트랜잭션 저장. 저장 대화상자·파일 선택은 발주서 내보내기처럼 함수를 주입해 테스트에서 가짜로 바꾼다.
- `lib/features/excel_import/` — 업로드 화면, 미리보기.
- 엑셀 읽기/쓰기는 이미 쓰는 `excel` 패키지, 파일 선택은 `file_picker`.

## 테스트

- **검증 (순수)**: 규칙마다 통과/실패 한 쌍. 날짜 형식 세 가지와 엑셀 날짜 셀, 오늘 이후 날짜, 환산계수 0·음수·글자, 쉼표가 잘못된 숫자, 시트·머리글 누락, 시트 안 중복 이름, 모르는 거래처·품목, 유통기한이 입고보다 이름, 줄 번호가 엑셀 번호와 같음, 오류 50개 상한.
- **저장 (DB)**: 새 거래처·품목·입고가 만들어지고 재고 합계가 `수량 × 환산계수`다. 이미 있는 거래처·품목은 새로 만들지 않는다. 기존 품목과 단위·환산계수가 다르면 오류. 도중 실패 시 전부 되돌려짐 (거래처만 만들어지고 입고가 실패하는 경우 포함). 입고 기록의 시각이 파일 날짜 09:00. 동기화 큐에 쌓임.
- **중복 의심**: 같은 파일을 두 번 올리면 두 번째에 중복 의심이 나온다. 한 항목이라도 다르면 나오지 않는다. 파일 안의 같은 줄끼리는 나오지 않는다.
- **화면**: 양식 받기가 저장 함수를 호출하고 만들어진 파일에 네 시트가 있다. 직원 세션에는 메뉴가 없다. 오류 파일은 올리기가 없고, 중복 의심은 체크해야 올리기가 켜진다. 성공하면 안내가 나오고 화면이 비워진다. 폭 320에서 넘치지 않는다.
- **변이 확인** (계획에 목록을 적는다): 오류 있어도 저장되게 함, 트랜잭션 제거, 환산계수 곱하기 제거, 날짜를 오늘로 저장, 중복 비교에서 매장 조건 제거, 기존 품목 불일치 검사 제거 — 각각 테스트가 실패해야 한다.

## 위험과 한계

- **한 번에 되돌리는 기능이 없다.** 잘못 올리면 입고를 하나씩 폐기·조정으로 바로잡아야 한다. 그래서 미리보기와 중복 경고를 두었고, 실제 데이터를 옮기기 전에 **개발용 서버에서 연습**하는 것을 권한다.
- 한 번에 많이 올리면 동기화로 서버에 보낼 행이 많아진다. 받는 쪽은 한 번에 1,000행까지만 받으므로 다른 기기에는 몇 번의 동기화에 걸쳐 도착할 수 있다 (기존 한계, 별도 작업 "paged pull").
- 이름이 같은 거래처·품목은 같은 것으로 본다. 공백이나 글자가 조금만 달라도 다른 것으로 보므로, 양식을 채울 때 이름을 통일해야 한다 (모르는 이름은 오류로 알려 준다).
- 엑셀 날짜 셀의 시간대나 1900/1904 날짜 체계 차이는 `excel` 패키지가 풀어 주는 값을 믿는다. 계획에서 실제 `.xlsx`로 확인한다.
- 환산계수와 단위를 사용자가 직접 적으므로 잘못 적으면 재고 수량이 틀린다. 안내 시트의 예시와 미리보기(품목별 환산 결과를 보여 주는 한 줄)로 완화한다.
